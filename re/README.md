# re\ - reverse-engineering data for UW.EXE

Reference data about the original program: `game\UW.EXE`, 547248 bytes, MD5 8afc3c29ef5667a3ab6667e8cbc8d63a. The
files are generated by tools or kept by hand. They hold no code. Do not hand-edit the generated ones; regenerate them
with their tool. `proved.txt` and `routines_status.txt` are the hand-kept ones, and CLAUDE.md sets the rules for them.

**Addresses.** Every file here gives addresses as **file offsets into UW.EXE**, in hex, six digits (for example
`012c37`). `uw_map.txt` also gives segment:offset. The load image starts at file offset 0x3200
(`tools\crosswalk.py`'s `IMG`).

## The files

### uw_map.txt - the routine map

Made by `tools\exe_map.py`. It lists 1909 routines and 66 overlays. Header:

```
# UW.EXE routines (tools/exe_map.py). file offset (segment:offset, or overlay stub + offset)
#   callers / calls: counts; msg: strings block 1 messages it prints; items: object ids it compares
```

One routine per line, then optional indented detail lines:

```
003273 (0000:0073)  callers 0  calls 1
    items: 40(a_rotworm)
```

It is the list of routines that `tools\checklist.py` (ROUTINES.md), `tools\crosswalk.py` and `tools\coverage.py`
work from.

### crosswalk.tsv - our addresses to underworld-exhumed's names

Made by `tools\crosswalk.py` from underworld-exhumed's `uw1\map\crosswalk.tsv` and `uw_map.txt`:

```
uv run --no-project python -I tools/crosswalk.py game/UW.EXE underworld-exhumed/uw1/map/crosswalk.tsv re/uw_map.txt re/crosswalk.tsv
```

Tab-separated, with one `#` header line and 1284 data rows:

| Column | Meaning |
| --- | --- |
| 1 | File offset (ours) |
| 2 | underworld-exhumed's name for the routine (a C name such as `LookAt`, or a listing label such as `seg001_023B_C` / `ovr153_D92`) |
| 3 | The matched source file and line in underworld-exhumed (`src/obj/LOOK.C:53`) |
| 4 | The size in bytes (hex) |

Use it to find a routine's original C by address (CLAUDE.md, the per-routine loop). `tools\proved.py` uses it to turn
a proof's routine names into offsets. Per `tools\crosswalk.py`'s docstring, underworld-exhumed's listing segments
are ours + 0x1ED paragraphs, and its overlays are numbered in the order of the overlay stubs.

### proved.txt - routines proved identical (hand-kept and tool-appended)

Each routine listed here has been run in the emulator beside our version on the same inputs, with every result,
driver call and state equal (CLAUDE.md's "proved"). Format, after the 3-line `#` header:

```
<file offset> <verifier> <name>
012c37 verify.py rand
```

Here `<verifier>` is the script that proved it: `verify.py`, `sfx_verify.py`, `songs_verify.py`, `collide_verify.py`,
or a core proof `proof_<file>.py`. There are 375 entries.

Lines are added by hand, or by `tools\proved.py` after a passing core proof, and only with a passing verifier run.
`tools\checklist.py` reads this file from beside `routines_status.txt` and marks these routines "proved".

### routines_status.txt - statuses kept by hand

The statuses `tools\checklist.py` cannot work out by itself. From its header:

```
<file offset> <status> <note>          a routine
seg <para> <status> <note>             a whole segment or overlay
status: ported | replaced | notneeded | todo     (a routine line wins over its segment's)
```

For example, `seg 0ec5 notneeded Borland C runtime ...` and `seg 0090 replaced VGA mode X drawing ...`. The
regeneration command is in CLAUDE.md:

```
uv run --no-project --with capstone python -I tools/checklist.py game/UW.EXE re/uw_map.txt re/routines_status.txt src ROUTINES.md
```

### coverage.txt - which original messages our engine prints

Made by `python -I tools\coverage.py` (added 2026-11-08 with EXE_AUDIT.md). It takes every message UW.EXE prints from
strings block 1 (`data\strings\block0001.txt`), grouped by the routine that prints it (from `uw_map.txt`), and checks
whether our engine's source (`src\*.c`) prints the same one (`str_get(1, N)` or the same text). Format:

```
<file offset> (<seg:off>)  items: ...
  MISS <n>: <message text>         (a message our source does not print)
```

The header gives the totals (15 ok, 75 missing). It measures `src\` (our own engine), not underworld-exhumed's port,
and it was last made on 2026-11-08.

### dis_*.txt - saved disassembly

Listings saved from `tools\dis16.py` (capstone, 16-bit), kept as references while those parts were decoded. Each line:

```
[>>]<file offset>  <bytes hex>  <mnemonic> <operands>
```

`>>` marks the instruction at the offset that was asked for. Branch targets are file offsets as well. To make a new
one:

```
uv run --no-project --with capstone python -I tools/dis16.py game/UW.EXE <file offset hex> [count] [back]
```
